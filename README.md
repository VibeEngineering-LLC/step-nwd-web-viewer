# step-nwd-web-viewer

Инструмент для просмотра 3D-файлов в браузере: превращает **STEP**, **3D-PDF (PRC)** и **Navisworks NWD** в модель GLB и собирает из неё одну HTML-страницу с навигацией и сечениями. Сервер не нужен: страницу можно открыть двойным щелчком, выложить на GitHub Pages или вставить в любую статику.

## Возможности страницы

- вращение, виды (изометрия, 6 сторон, «Вписать»), клавиши `1–6`, `F`, `Esc`, `H`;
- дерево «Состав» (свёрнуто по умолчанию), слияние одинаковых деталей (`Ручка ×6`), показ/скрытие, «Только это»;
- выбор щелчком с подсветкой и габаритом `Д × В × Ш`, мм;
- разнесение сборки 0–100 %, рентген, сетка, рёбра, светлая/тёмная тема, телефонная вёрстка;
- сечения: простое (оси X/Y/Z с переворотом) и расширенный модуль для NWD — плоскость X/высота/Z, коробка из шести плоскостей, «по выделенному», планы этажей, заливка разреза;
- **ссылка на настроенный вид:** ракурс, сечения, скрытые и выбранные детали, разнесение, рентген/сетка/рёбра записываются в адрес (`#…`), кнопка «Ссылка» в панели видов копирует его; открытие такой ссылки восстанавливает вид (см. ниже).

## Ссылка на настроенный вид

Состояние вьюера хранится в хеше адреса, отдельный сервер не нужен. Пример:

```
https://example.org/model/#c=10,8,12,0,2,0&h=1-3.7&s=5&xray=1&secMode=plane&secAxis=x&secPos=-9.5&secFlip=1
```

| Ключ | Что хранит |
|---|---|
| `c` | камера: позиция и цель, `px,py,pz,tx,ty,tz`, м |
| `h` / `s` | индексы скрытых / выбранных деталей (`1-3.7` = 1,2,3,7) |
| `xray`, `grid`, `edges`, … | переключатели (`1` вкл., `0` выкл.); пишутся только отличающиеся от умолчаний |
| `explode` | разнесение, % |
| `secMode`, `secAxis`, `secPos`, `secFlip`, `secBox…` | сечение NWD-страницы (режим, ось, положение, обращение, коробка) |
| `clipOn`, `clipAxis`, `clipPos`, `clipFlip` | сечение простой (STEP) страницы |

Адрес обновляется автоматически через 0,7 с после изменения. Индексы деталей относятся к конкретной модели: после замены `model.glb` старые ссылки могут показывать другие детали. Модуль — `assets/share_module.js`, уже встроен в `assets/viewer-template.html`.

## Что входит

| Путь | Назначение |
|---|---|
| `scripts/step2glb.py` | STEP → GLB через OpenCascade (OCCT): дерево сборки, имена деталей |
| `scripts/glb_rename_root.py` | переименовать узел в GLB (обезличивание перед публикацией) |
| `scripts/prc/` | 3D-PDF (PRC) → GLB без Adobe Acrobat; `vendor/` — сторонний файл под LGPL-3.0 |
| `scripts/nwd/` | NWD → GLB: дампер на C++, конвертер, проверка площадей, квантизация, сборка страницы |
| `assets/viewer-template.html` | вьюер на three.js 0.160.0 (библиотека подгружается из CDN) |
| `assets/section_module.js` | модуль сечений для NWD |
| `assets/share_module.js` | вид в адресе и кнопка «Ссылка» (встроен в шаблон) |
| `docs/nwd-pipeline.md` | подробный порядок работы с NWD |
| `docs/pitfalls.md` | найденные дефекты и проверки приёмки |

## Требования

- Python 3.12 (для STEP и PRC: `cadquery-ocp`; для PRC ещё `pymupdf`, `trimesh`, `numpy`; для NWD: `numpy`);
- для NWD ещё: компилятор C++20 (MSVC 2022 или GCC/Clang), CMake ≥ 3.20, парсер `nwd-reader` (см. «NWD» ниже);
- браузер с WebGL.

```bash
pip install cadquery-ocp numpy trimesh pymupdf
```

## Быстрый старт: STEP

1. Конвертация (третий аргумент — допуск сетки в мм; для изделия около 2 м хватает 0.5):

   ```bash
   python scripts/step2glb.py model.step model.glb 0.5
   ```

2. Проверка результата — не по коду возврата, а по содержимому: число узлов и мешей, имена деталей. Пустая сцена или имена вида `NAUO1…` — дефект (см. `docs/pitfalls.md`).

3. Сборка страницы из шаблона (заголовок, подзаголовок, имя модели):

   ```bash
   sed -e 's#{{TITLE}}#Моя сборка#g' -e 's#{{SUBTITLE}}#Сборка · N деталей#g' \
       -e 's#{{MODEL_NAME}}#Моя сборка#g' assets/viewer-template.html > viewer.html
   ```

   Шаблон — фрагмент без `<html>`/`<head>`/`<body>`. Для самостоятельной страницы оберните его в документ с `<meta charset="utf-8">` (без неё кириллица превращается в «кракозябры»).

4. Модель загружается из `window.MODEL_B64` (base64 внутри страницы), а если переменной нет — через `fetch('model.glb')` рядом со страницей.

   - **Автономный файл:** поместите `<script>window.MODEL_B64="…"</script>` с base64 вашего GLB перед скриптом вьюера.
   - **Статика/Pages:** положите `index.html` и `model.glb` рядом.

5. Локальная проверка (`file://` для `fetch` не подходит):

   ```bash
   python -m http.server 8000 --bind 127.0.0.1
   ```

   Откройте `http://127.0.0.1:8000/`. Приёмка: консоль без ошибок; число деталей в дереве равно числу мешей в GLB; щелчок меняет карточку и габарит; разнесение двигает детали; сечение режет; на ширине 375 px нет горизонтальной прокрутки.

Цвета деталей задаёт массив `TINTS` в шаблоне (регулярка по имени → цвет); по умолчанию все светло-серые.

## 3D-PDF (PRC)

```bash
python scripts/prc/prc2glb.py in.pdf out.glb
```

Интерпретаторы шагов можно задать переменными окружения `PRC_PY_FITZ`, `PRC_PY_OCP`, `PRC_PY_TRI`, `PRC_OCP_SITE` (по умолчанию — текущий Python). Проверяйте результат по строкам `Leaf parts with mesh: N` и `Missing leaf parts: none`, а габарит сверяйте с исходной моделью.

В странице для такой модели поставьте `window.FIX_PRC_MESH = true` **до** скрипта вьюера, иначе модель будет чёрной (грани в сетке PRC развёрнуты).

Ограничения: разобраны версии PRC, встречавшиеся при отработке (SolidWorks, версия формата 7094); четыре места формата восстановлены по данным, а не по спецификации; цвета не переносятся. **Если есть STEP — берите его:** он точнее.

## NWD (Navisworks)

Формат NWD закрыт. Для чтения используется сторонний открытый парсер [`nwd-reader`](https://github.com/1817716374/nwd-reader) (C++20). **В этот репозиторий он не входит**: на момент написания у него нет лицензии, поэтому распространять его нельзя. Склонируйте и проверьте его сами (чужой код — прочитайте и просканируйте до сборки и запуска), затем:

```bash
cmake -S scripts/nwd -B build -DNWD_READER_DIR=/путь/к/nwd-reader
cmake --build build --config Release
```

Конвейер (подробно — `docs/nwd-pipeline.md`):

```bash
nwd_dump model.nwd out/                       # scene.json + geoms.bin
python scripts/nwd/nwd2glb.py out/ model.glb report.json
python scripts/nwd/check_area.py out/ model.glb   # обязательная приёмка по площадям
python scripts/nwd/quantize_glb.py model.glb model_q.glb   # по желанию, если файл велик
python scripts/nwd/build_viewer.py assets/viewer-template.html assets/section_module.js viewer.html "Заголовок" "Подзаголовок"
```

Планы этажей добавляются в страницу до скрипта вьюера:

```html
<script>window.SECTION_PRESETS=[{name:"1 этаж", y:1.5},{name:"2 этаж", y:4.5}];</script>
```

Цвет в странице — по системам `IfcSystem` (палитра по семействам). Видимость берётся из `NodeOverrides` файла: в цепочках версий скрыто большинство старых источников.

## Ограничения и честные оговорки

- Выбор щелчком для NWD — на уровне системы/категории, а не отдельного элемента; свойства элементов в страницу не переносятся.
- Большинство сеток NWD открытые (не замкнутые), поэтому заливка разреза по умолчанию выключена.
- Цилиндры/окружности и точки (типы 104/105) на проверенном файле не встречались; дампер их не разворачивает.
- Проверено на нескольких реальных файлах, автоматических тестов в репозитории нет.
- Страница подгружает three.js из CDN: офлайн нужен локальный экземпляр библиотеки.
